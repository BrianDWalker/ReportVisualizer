# 1.2.7 inactive-view verification

## Change

Previously, opening Results Visualizer registered result-model listeners and
Display-wide focus/selection filters until the view was disposed. Hiding the
tab or using another workbench part did not suspend the service. Model events
could therefore copy every fetched row on the UI thread and rebuild charts
while the visualizer was not being used. This is a plausible source of UI
stalls and allocation pressure; it does not establish the cause of a particular
DBeaver crash.

The service now starts paused. `ViewActivityTracker` enables observation only
when the visualizer is the active, visible part and its window is foreground
and not minimized. Shell and content lifecycle events also suspend it. Pausing
removes the result listener and global SWT filters and invalidates already
queued refresh/selection callbacks. Returning schedules one fresh source read,
compares data, and rebuilds only when necessary. Cached chart/session settings
remain available. Explicit Source Query jobs can finish in the background;
completion delivery waits for source revalidation on return. The completion
buffer retains at most 20 sessions and keeps the newest request per session.
Closing removes listeners and clears pending completions and controller refs.

## Runtime follow-up

Native DBeaver UI interaction and crash reproduction were not performed for
this release. After installing 1.2.7 and restarting DBeaver:

1. Run a query, select Results Visualizer, and confirm the chart appears.
2. Return to the SQL editor and rerun or edit the results repeatedly. The
   visualizer should retain its previous chart while inactive; selecting it
   should show the latest results and preserve compatible configuration.
3. Stack the visualizer behind another tab, hide it, minimize DBeaver, and
   switch to another application. Confirm no unattended chart updates; return
   and confirm one catch-up refresh. Repeat with a detached visualizer window.
4. Execute an explicit Source Query, leave the view before it completes, and
   return. Confirm the result is applied only after return and that a changed
   source invalidates a stale aggregate.
5. Close and reopen Results Visualizer. Confirm the new view works and the
   disposed instance receives no late updates.
